## O que faz
Move o ponteiro do branch atual (e o HEAD) para outro commit. Dependendo do modo, também altera a área de staging e o diretório de trabalho. É a ferramenta para **desfazer commits locais**, reescrevendo o histórico do branch.

## Uso
```bash
git reset --soft  HEAD~1
git reset --mixed HEAD~1    # igual a: git reset HEAD~1
git reset --hard  HEAD~1
git reset arquivo.txt       # só tira o arquivo do staging
```

## Flags úteis
- `--soft` — move o branch e **mantém** as mudanças daqueles commits no staging. Útil para refazer o último commit ou juntar vários commits em um.
- `--mixed` (padrão) — move o branch e **tira as mudanças do staging**, mas elas continuam nos arquivos.
- `--hard` — move o branch e **descarta** as mudanças do staging e dos arquivos rastreados. Perigoso: alterações não commitadas se perdem de vez.
- `--keep` — como `--hard`, mas aborta se for sobrescrever alterações locais.

## Exemplo
```bash
# desfazer o último commit, mantendo o trabalho para recommitar
git reset --soft HEAD~1

# juntar os 3 últimos commits em um só
git reset --soft HEAD~3
git commit -m "feature completa"

# voltar o branch para o estado do remoto, jogando fora tudo local
git fetch origin
git reset --hard origin/main
```

`HEAD~1` é o commit pai do atual; `HEAD~3`, três commits antes.

Regras práticas:
- Use `reset` só em commits que **ainda não foram publicados**. Em commits já enviados ao remoto, prefira `git revert`, que cria um commit novo desfazendo as mudanças sem reescrever o histórico dos outros.
- Arquivos novos não rastreados não são apagados por `--hard`; para isso existe `git clean`.
- Se fizer um `reset --hard` errado, os commits "perdidos" continuam recuperáveis por um tempo pelo `git reflog`.
- Para desfazer alterações de arquivos sem mexer em commits, o comando moderno é `git restore`.
