## O que faz
`ps` lista processos; `kill` envia um **sinal** a um processo pelo PID. Apesar do nome, `kill` não só mata: ele entrega qualquer sinal, e o processo decide como reagir à maioria deles.

## Uso
```bash
ps aux                          # todos os processos, formato BSD
ps -ef                          # todos, formato System V
ps aux --sort=-%mem | head      # os que mais usam memória
pgrep -a python                 # PID e linha de comando por nome
kill 1234                       # envia SIGTERM (15)
kill -9 1234                    # envia SIGKILL
pkill -f "servidor.py"          # por padrão na linha de comando
killall firefox                 # por nome exato
```

## Flags úteis
Sinais mais usados (`kill -l` lista todos):
- `SIGHUP` (1) — terminal fechado; muitos daemons usam como "recarregue a configuração".
- `SIGINT` (2) — o que o Ctrl+C envia.
- `SIGKILL` (9) — encerra na hora; **não pode** ser capturado nem ignorado.
- `SIGTERM` (15) — pedido educado de encerramento; é o padrão do `kill`.
- `SIGSTOP` / `SIGCONT` — pausa e retoma (o Ctrl+Z envia `SIGTSTP`, uma versão que pode ser tratada).

## Exemplo
```bash
# achar quem está usando a porta 8000 e encerrar
ss -ltnp | grep 8000
kill 48213
sleep 5; kill -0 48213 && kill -9 48213   # força só se ainda estiver vivo
```

Por que tentar `SIGTERM` antes de `SIGKILL`: com `SIGTERM`, o programa pode fechar arquivos, terminar transações, apagar arquivos temporários e liberar travas. O `SIGKILL` tira tudo isso dele, podendo deixar dados corrompidos ou arquivos de lock para trás. `kill -0 PID` não envia nada; só testa se o processo existe e se você tem permissão para sinalizá-lo.

Para acompanhar em tempo real, `top` (ou `htop`, mais amigável) mostra CPU e memória por processo e permite enviar sinais pela interface. Na coluna `STAT` do `ps`, `R` é rodando, `S` dormindo, `D` esperando I/O sem poder ser interrompido, `T` parado e `Z` zumbi.
