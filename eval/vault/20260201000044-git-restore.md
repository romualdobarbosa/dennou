## O que faz
Restaura **arquivos** no diretório de trabalho ou na área de staging, sem mexer em commits nem no branch. Existe desde o Git 2.23, separando essa função do antigo `git checkout -- arquivo`.

## Uso
```bash
git restore arquivo.py             # descarta alterações não staged
git restore --staged arquivo.py    # tira do staging, mantém a alteração no arquivo
```

## Flags úteis
- `--staged` (`-S`) — atua no index em vez do diretório de trabalho.
- `--source=<commit>` — restaura o conteúdo de um commit específico.
- `--worktree --staged` — restaura os dois de uma vez.

## Exemplo
```bash
git restore --source=HEAD~2 config.yaml   # versão de 2 commits atrás
git restore .                              # descarta tudo que não foi staged
```

Alterações descartadas com `git restore` (sem `--staged`) não podem ser recuperadas pelo Git.
