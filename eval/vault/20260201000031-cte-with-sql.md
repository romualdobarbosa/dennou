## O que é
CTE (Common Table Expression) é uma consulta nomeada, definida com `WITH`, que pode ser referenciada como se fosse uma tabela na consulta principal. Serve para quebrar consultas longas em passos legíveis e para consultas **recursivas**.

## Sintaxe
```sql
WITH nome AS (
    SELECT ...
),
outro AS (
    SELECT ... FROM nome
)
SELECT * FROM outro;
```

## Exemplo
```sql
WITH totais AS (
    SELECT cliente_id, SUM(valor) AS total
    FROM pedidos
    GROUP BY cliente_id
),
media AS (
    SELECT AVG(total) AS media_geral FROM totais
)
SELECT t.cliente_id, t.total
FROM totais t, media m
WHERE t.total > m.media_geral;
```

CTE recursiva para percorrer hierarquias, como um organograma em que cada funcionário aponta para o gestor:

```sql
WITH RECURSIVE subordinados AS (
    SELECT id, nome, gestor_id, 1 AS nivel
    FROM funcionarios
    WHERE id = 1                          -- ponto de partida (âncora)
    UNION ALL
    SELECT f.id, f.nome, f.gestor_id, s.nivel + 1
    FROM funcionarios f
    JOIN subordinados s ON f.gestor_id = s.id   -- passo recursivo
)
SELECT * FROM subordinados;
```

A parte recursiva roda repetidamente, usando as linhas produzidas na iteração anterior, até não gerar mais nenhuma linha.

## Gotchas
- PostgreSQL, SQLite e MySQL 8+ exigem a palavra `RECURSIVE`; o SQL Server não usa essa palavra.
- Uma CTE recursiva sem condição de parada (ou com ciclo nos dados) roda até estourar um limite ou indefinidamente. Adicione um limite de nível (`WHERE s.nivel < 20`) quando os dados não forem confiáveis.
- Até o PostgreSQL 11, toda CTE era materializada e funcionava como uma barreira de otimização. Do 12 em diante, CTEs não recursivas referenciadas uma vez podem ser incorporadas à consulta principal; `AS MATERIALIZED` e `AS NOT MATERIALIZED` controlam isso explicitamente.
